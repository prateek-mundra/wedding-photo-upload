# Wedding Photo Upload System — MVP

Guests scan a QR code → open a web page → upload photos/videos → files land
in a Google Drive folder, organized by event. No app install, no guest login.

## Stack (v1)

- **Backend:** FastAPI (Python)
- **Storage:** Google Drive (service account + shared folder)
- **Frontend:** Plain HTML/CSS/JS (no build step, fast on any phone)
- **QR:** `qrcode` Python library

## 1. Google Drive setup (one-time)

1. Go to [Google Cloud Console](https://console.cloud.google.com/) → create a project.
2. Enable the **Google Drive API** for that project.
3. Create a **Service Account** (IAM & Admin → Service Accounts).
4. Generate a JSON key for it → download → save as `backend/service_account.json`.
5. In your own Google Drive, create a folder, e.g. "Nicku & Shruti Wedding Photos".
6. **Share** that folder with the service account's email
   (looks like `wedding-uploader@your-project.iam.gserviceaccount.com`) as **Editor**.
7. Copy the folder ID from its URL (`drive.google.com/drive/folders/<THIS_PART>`).

## 2. Backend setup

```bash
cd backend
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# edit .env: set DRIVE_ROOT_FOLDER_ID, and APP_BASE_URL once you know it

# place service_account.json in this backend/ folder

uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Guest upload page: `http://localhost:8000/app/index.html?event=wedding`

## 3. Generate printable QR codes

```bash
cd qr
pip install qrcode[pil]
python generate_qr.py --base-url http://localhost:8000 --out ./out
# once deployed: python generate_qr.py --base-url https://photos.yourdomain.com
```

## 4. Admin gallery

Visit `http://localhost:8000/app/admin.html`. It'll ask for the `ADMIN_TOKEN`
you set in `.env` (pick any long random string), then shows a live,
auto-refreshing grid of everything uploaded per event — this is how you
check uploads are actually landing in Drive without digging through the
Drive UI. Token is stored in the browser's localStorage after first login.

## 5. API quick reference

| Method | Path                    | Auth              | Purpose                                |
|--------|--------------------------|-------------------|------------------------------------------|
| POST   | `/api/upload`            | none (public)     | Guest uploads a file (multipart form)  |
| GET    | `/api/gallery/{event}`   | `X-Admin-Token`   | List uploaded files for an event       |
| GET    | `/api/qr/{event}`        | none              | Get a QR PNG on the fly                |
| GET    | `/health`                | none              | Healthcheck                            |

Interactive API docs (auto-generated by FastAPI): `http://localhost:8000/docs`

## Code layout

- `main.py` — routes only; thin, delegates to other modules
- `config.py` — typed settings loaded from `.env` (fails fast if misconfigured)
- `schemas.py` — Pydantic request/response models (also power the `/docs` page)
- `auth.py` — admin token dependency for protected routes
- `drive_service.py` — the only file that knows about Google Drive; swap this for R2/S3 later without touching anything else

## Known v1 limits (by design — keep it simple first)

- No face recognition yet (Phase 3 in the roadmap below).
- No database — file list comes live from the Drive API.
- No guest auth — anyone with the QR/link can upload (fine for a wedding).
- Admin gallery uses one shared token, not per-user accounts — fine for a single family/photographer team.
- Google Drive free tier caps at 15GB; monitor usage, especially video.
- Not yet deployed anywhere — runs locally until you put it on a VPS.

**Don't forget to set `ADMIN_TOKEN` in `.env`** — without it, `/api/gallery/*` stays locked (fails closed, by design).

## Before the wedding — deployment checklist

- [ ] Deploy backend to a small VPS (2GB RAM is plenty) or a platform like Railway/Render.
- [ ] Point a real domain + HTTPS at it (QR codes should use `https://`).
- [ ] Set `allow_origins` in `main.py` CORS config to your real domain, not `*`.
- [ ] Load-test with ~20-30 simulated concurrent uploads before the big day.
- [ ] Print QR codes (one per event) and place at entry points / tables.
- [ ] Do a dry run at a smaller pre-wedding event (Haldi/Mehendi) first.

## Roadmap (matches your original plan)

1. **Phase 1 (this MVP):** QR → upload → Google Drive, event-wise folders. ✅ built here
2. **Phase 2:** Photographer bulk upload tool (zip → auto-extract → Drive), basic admin gallery view.
3. **Phase 3:** Face recognition — InsightFace for embeddings, FAISS for similarity search, "find my photos" via selfie.
4. **Phase 4:** Polish — compression before upload, duplicate detection, download-all-as-zip, live-refreshing gallery.

## Migrating off Drive later

The only file that knows about Drive is `backend/drive_service.py`. To move
to Cloudflare R2 (or S3/Backblaze) later, swap that module for one using
`boto3` against R2's S3-compatible endpoint — `main.py` doesn't need to change.
